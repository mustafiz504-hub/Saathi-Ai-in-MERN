**Google Authentication: Client se Server tak ki Kahani (Detailed)**

Pehle hamara authentication sirf browser tak tha, par ab humne pura cycle complete kar liya hai:

1.  **Frontend ka role:** User jab Google button pe click karta hai, to browser use Google ke login page pe le jata hai. Wahan se ek temporary 'Authorization Code' milta hai.
2.  **Server tak Code bhejna:** Hamara frontend uss code ko `/auth/google` API ke zariye backend (Node.js) ko bhejta hai.
3.  **Google se handshake (Backend):** 
    - Server uss code ko Google ke pass wapas bhejta hai aur kehta hai, "Bhai, ye code sahi hai? Iske badle mujhe User ki details do."
    - Google verify karke `access_token` deta hai, jise use karke hum User ka **Naam, Email, aur Profile Picture** nikal lete hain.
4.  **Database check:** Hum system me check karte hain ki ye user pehle kabhi aaya hai ya nahi. Agar pehle se entry hai to use login kar dete hain, nahi to naya account (`social-logins` collection me) create kar dete hain.

**Security Update: httpOnly Cookies (Ye kyu zaruri hai?)**

Login hone ke baad, humne normal local-storage ke bajaye **httpOnly Cookie** ka use kiya hai.
- **Kyu?**: Local storage me token rakhne se hackers browser ki scripts use karke use chura sakte hain (XSS attack). 
- **Fayda**: `httpOnly` flag ki wajah se browser ki JavaScript uss cookie ko 'dekh' ya 'read' nahi kar sakti. Sirf browser hi use automatically har request ke sath server pe bhejta hai. Isse hamara session ekdum secure ho gaya hai.

**Messaging System: Models aur unka Rishta**

Humne 2 alag models banaye hain jo milkar chat chalate hain:

1.  **Conversation Model (The Hub):** 
    - Iska kaam hai ye record rakhna ki "Kaun log aapas me baat kar rahe hain?". 
    - Jaise ki, "Mustafiz" aur "Anakin" ke beech ek conversation ID ban jayegi. Isme dono ki User IDs store hongi.
    - Saath hi, ye conversation apne andar un saare Messages ki **List (Array)** rakhta hai jo in dono ne ek-dusre ko bheje hain.

2.  **Message Model (The Data):**
    - Har ek message (Jaise: "Hello, kaise ho?") yahan save hota hai.
    - Isme ye bhi record hota hai ki ye message kisne bheja (senderId) aur kise mila (receiverId).

3.  **Combine kaise hote hain?**: 
    - Jab hum chat open karte hain, to server `Conversation` ko check karta hai aur `.populate("messages")` use karke uss array ke andar ki IDs ko real message text me convert karke frontend pe bhej deta hai.
